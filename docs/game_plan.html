1The Problem & User

WhoRevenue analysts, market/destination managers and executives. They know the business but don't write SQL.
Daily headacheEvery revenue or booking question ("What was revenue last quarter?", "Which destinations are growing?") becomes a ticket to the data team and takes hours to days. Teams also calculate "revenue" differently: some include pending or cancelled bookings, some don't.
What we buildA Genie AI Agent on governed Gold views that answers in plain English, wrapped in a Databricks App: a chat page showing the answer, a result table and the SQL used.

2The Data (5 Tables)

Source: Unity Catalog samples.wanderbricks, plus an equivalent synthetic dataset in the repo (data/csv/, seeded generator) for demos and testing. Star schema with bookings as the fact table; destination is reached through properties.

Cleanup verified: the synthetic data contains 300 deliberately dirty rows (150 messy status values, 75 duplicates, 40 bad date ranges, 20 null and 15 negative amounts). The Gold layer reduces bookings from 10,075 to 9,925 clean rows with 3 status values (confirmed, pending, cancelled) and 0 duplicates. Joins add no extra rows.

Gold views (wanderbricks_genie.gold): fact_bookings, dim_property, dim_guest, dim_host, and the wide Genie-friendly v_booking_revenue.

Business rules given to the agent

  • Revenue = SUM(total_amount) where status = 'confirmed' only. Pending and cancelled bookings are never counted.
  • Bookings with no status mentioned = confirmed bookings.
  • Average Booking Value = confirmed revenue ÷ confirmed bookings. Length of stay = datediff(check_out, check_in).
  • Revenue and stay questions use check-in date; "bookings made in…" uses created date. "Last quarter" = previous full calendar quarter.
  • Never return guest or host personal details.
